[3.1.1内存基础知识](311内存基础知识/index.md)
  # 指令的原理
  开发者在写完代码后会编译，编译会将代码翻译为一条条的指令，指令有3部分：
  ```c
操作码，内存地址1，内存地址2
  ```
  - 机器识别操作码知道该做什么操作
  - 识别内存地址知道在哪里操作
  # 逻辑地址/物理地址
  程序在编译后形成的可执行文件叫装入模块
  - 装入模块中的指令使用的是相对地址而不是绝对地址
  具体如何对应物理地址则是装入方式决定的
  # 三种装入方式
  ### 绝对装入
  编译后直接就是绝对地址，直接把内容写到绝对地址上
  特点：直接操作地址，移植性差，不安全
  ### 静态重定位
  编译后是相对地址，在装入内存时进行重定位（转换成物理地址）
  特点：需要连续的内存，装入后无法移动，也不能在运行中申请
  ### 动态重定位（现代操作系统）
  编译后是相对地址，装入内存时不立即转换成物理地址，执行时才转换成物理地址
  # 链接的三种方式
  一个程序写完后需要经历编译→链接的过程，这里讨论的就是链接的方式
  ### 静态链接
  编译完了就链接，不再拆开
  ### 装入时动态链接
  在装入内存时才链接
  ### 运行时动态链接
  在运行时才链接

[3.1.1覆盖与交换](311覆盖与交换/index.md)
  # 覆盖技术
  早期计算机内存小，会将程序分为多个段，常用的段常驻内存，不常用的需要在调入内存
  内存分一个固定区和若干覆盖区

  # 交换技术
  在系统内存不足时将内存中部分进程换出外存，时机合适再换回
  - 换出外存的状态叫挂起态
  - 挂起还可以分为就绪挂起，阻塞挂起
  - 被挂起的进程放在外存对换区中（连续分配，速度快）
  - 普通文件放在文件区（随机分配，速度慢）
  - PCB常驻内存，不会被换出外存
[3.1.2内存分配-连续分配](312内存分配-连续分配/index.md)
  # 单一连续分配
  将内存分为系统区和用户区两个部分
  - 用户区只能有一个用户程序，该进程独占用户区
  优点：简单，不用考虑内存保护，无外部碎片
  缺点：内存利用率低，一次只能运行一个进程，有内部碎片（分配的内存有大片未利用）
  # 固定分区大小
  将内存分为系统区和若干大小相等的用户区
  或
  将内存分为系统区和若干大小不等的用户区
  - 每个分区可以装入一个进程
  - 操作系统会维护一个分区说明表，用来记录各分区大小，起始地址，分配状态等
  优点：实现简单，无外部碎片
  缺点：无法满足超大进程（各分区都放不下），会产生内部碎片，利用率低
  # 动态分区分配
  系统不提前分区，在进程装入内存时才根据大小建立分区，且分区大小可变
  - 系统`维护空闲分区`表或`空闲分区链`来记录分区情况
  - 使用`动态分区分配算法`决定分区如何分配

  # 名词解释
  内部碎片：分配给进程的内存存在部分未被利用
  外部碎片：内存产生了一些难以利用的空闲区域
  PS：可以通过紧凑技术解决外部碎片（移动其他进程内存）
[3.1.2动态分区分配算法](312动态分区分配算法/index.md)
  动态分区分配算法解决内存怎么分，分那个块的问题
  # 首次适应算法
  思想：从低地址查找，找到第一个能满足大小的分区
  实现：系统维护一个空闲分区表或空闲分区链来确定怎么分（按地址顺序排列）
  优点：不用重排链表
  缺点：每次都从空闲分区表/链头遍历，开销大
  # 最佳适应算法
  思想：优先分配小空间
  实现：系统维护一个空闲分区表或空闲分区链来确定怎么分（不过这个表/链是按从小到大的顺序排列）
  缺点：有太多外部碎片
  # 最坏适应算法
  思想：优先分配大空间
  实现：系统维护一个空闲分区表或空闲分区链来确定怎么分（不过这个表/链是按从大到小的顺序排列）
  缺点：大进程容易得不到内存
  # 临近适应算法
  思想：改进首次适应算法，改从上次查找结束时的位置开始查找，找到首个适应的大小
  实现：系统维护一个空闲分区表/链（按地址顺序排列），从上次查找的地方继续
  优点：不用重排链表，解决了首次适应算法的问题
  缺点：大内存进程容易没内存
[3.1.3分页内存管理](313分页内存管理/index.md)
  # 什么是分页存储
  分页存储是一种内存管理方式，它可以较好的利用虚拟内存并解决外部碎片的问题
  原理：
  系统将内存分成固定大小的“页”，将程序也切分为和页大小一样的若干份，并将它们装入页中
  - 操作系统将内存分为多个大小相同的分区，每个分区就是一个页框
  - 每个页框有一个编号，页框号从0开始
  - 将一个进程分成多个和页框大小一样的块，并放入页框
  - 操作系统为每个进程维护一个页表

  # 术语：
  页框=页帧=内存块=物理块=物理页面
  页表长度：页表中页表项（Page Table Entry，PTE）的数量，也就是该进程拥有的页数。
  # 重要数据结构—页表
  系统为每个进程维护一个页表，用于记录页面在内存中的位置（映射页号和块号）
  - 页表记录的是块号，不是内存地址
  - 页表类似于顺序表，不用专门记录页号
  - 页表在内存中是连续存储的
  # 地址转换
  1. 页号=逻辑地址/页面长度（取整）
  （逻辑地址都是从0开始的）
  1. 页内偏移量=逻辑地址%页面长度（取余）
  1. 查询页表，可知道页框号
  1. 页起始地址=页框号×页面大小
  1. 实际物理地址=页起始地址+页面偏移量
  # 分页的优点
  1. 没有外部碎片：
  程序页面可以分散存放，不需要连续空间，因此几乎没有外部碎片。
  1. 支持虚拟内存：
  程序看到的是连续的大地址空间（这对程序是透明的）
[3.1.3分页内存管理的软硬件](313分页内存管理的软硬件/index.md)
  本节讲的是如何通过硬件实现地址变换
  # 页表寄存器
  页表寄存器用来存放
  - 页表起始地址
  - 页表长度
  # 地址变换过程
  （跟上节的过程一样，多了个检查页号合法性）
  1. CPU给出逻辑地址
  1. 算出页号
  页号=逻辑地址/页面长度
  1. 检查页号是否合法
  检查页表寄存器，如果页号≥页表长度，则触发越界中断
  1. 计算页内偏移量
  页内偏移量=逻辑地址%页面长度
  1. 检查页表，找到块号
  1. 计算物理地址
  物理地址=块号x页面长度+页内偏移量

[3.1.4分段内存管理](314分段内存管理/index.md)
  # 什么是分段内存管理
  与分页内存管理不同，分段不是死板的将内存分为几个固定的区域，而是按逻辑功能分为几个“段”
  如：
  代码段（程序指令）
数据段（全局变量）
堆（动态分配内存）
栈（函数调用和局部变量）
  # 分段地址结构
  分段内存管理的逻辑地址与一般的不同，它是这种格式
  ```plain text
逻辑地址 = <段号, 段内偏移量>
  ```
  # 地址转换过程
  操作系统维护一张段表
  表包含：段基址（段起始地址），段长度
  地址转换↓
  ```plain text
逻辑地址→检查是否越界→计算物理地址
物理地址=段基址+段内偏移量
  ```
  # PS
  - 分页对用户是透明的，分段对用户不透明
  - 分段可以更好的保护信息和进程安全
  - 分段更容易实现共享
[3.1.5段页式内存管理](315段页式内存管理/index.md)
  段页式内存管理结合了分段和分页的优点
  核心思想：
  > 先按程序逻辑分段，再把每个段划分成固定大小的页。
  # 段页式内存管理逻辑地址结构
  ```plain text
<段号, 页号, 页内偏移>
  ```
  # 地址转换过程
  第一步：查段表
  第二步：查页表
  第三步：形成物理地址
[3.2.1虚拟内存](321虚拟内存/index.md)
  # 传统内存管理算法缺点
  - 碎片问题（内部碎片和外部碎片）
  - 内存利用率不足，无法支持比物理内存更大的程序运行
  - 内存中存在大量使用率低的数据
  # 局部性原理
  时间局部性
  如果一个数据被访问过，那么在不久的将来很可能再次被访问。
  空间局部性
  如果访问了某个存储单元，那么其附近的存储单元很可能很快被访问
  # 虚拟内存特性
  多次性（离散性）
  一个程序不必一次全部装入内存，可以分批装入
  对换性（交换性）
  当内存空间不足时，将暂时不用的页面换出到磁盘，需要时再换入内存
  虚拟性
  逻辑上扩充了内存容量，对用户透明
  # 虚拟内存的实现方式
  主要有三种：
请求分页系统（基于分页内存管理）
请求分段系统（基于分段内存管理）
请求段页式系统（基于段页式内存管理）
  PS
  相对于传统的离散内存管理，虚拟内存技术多了两个功能：
  - 请求调页/段（缺页/段时）
  - 页面/段置换（内存不足时）
  虚拟内存基于分页内存管理，实现了内存扩展
[3.2.2请求分页内存管理](322请求分页内存管理/index.md)
  # 页表机制
  普通页表中: 
  | 页号 | 块号 |
  | --- | --- |
  | 1 | 5 |
  | 2 | 3 |
  请求分页中增加状态位: 
  | 页号 | 块号 | 状态位 |
  | --- | --- | --- |
  | 1 | 5 | 0 |
  | 2 | 3 | 1 |
  其中状态位：
  0→不在内存中（缺页）
  1→在内存中
  # 缺页中断机制
  当发生缺页时，
  有空闲内存→直接调入
  无空闲内存→使用页面置换机制淘汰一个页面
  PS：
  缺页属于内中断的中的故障中断
  ```mermaid

    D --> I[I/O设备请求]

  ```
[3.2.4页面置换算法](324页面置换算法/index.md)
  # opt最佳置换算法
  淘汰未来最长时间内不会再被访问的页面
  优点：缺页率最低
  缺点：实现不了（在实际中不可能知道未来要访问哪些页面）
  # FIFO先进先出置换算法
  淘汰最早进入内存的页面
  优点：实现简单
  缺点：可能频繁淘汰高频使用的页，造成严重缺页（Belady异常）
  # LRU最近最久未使用置换算法
  淘汰当前内存中最长时间未被使用的页
  实现：在页表中新增一个访问字段，用来记录该页上次使用时间
  优点：缺页率低
  缺点：实现较复杂，开销大
  # clock时钟置换算法
  ### 简单时钟置换算法
  给页表中加一个访问位，用来记录最近是否被访问，用一个指针循环扫描各页的访问位并将其翻转，规则
  - 扫描到0且缺页时则将该页换出
  - 扫描到1则不换出
  ### 改进型时钟置换算法
  基于简单时钟置换算法改进
  其在页表中新增了一个修改位，记录页是否被修改，1→修改过；0→未修改，
  依旧用一个指针循环扫描各页的访问位并将其翻转，规则（访问位，修改位）
  - 扫描到（1，1）不会淘汰
  - 扫描到（0，0）直接淘汰
  - 扫描到（0，1）备选淘汰（没有（0，0）的情况）
  - （1，0）不用说了，扫描完就翻转成（0，0）了
  PS：
  **改进关键：算法淘汰（0.，0）的块是直接丢弃，不是写回外存（因为没改），降低了IO频率**
  什么？你问我全是（1，1）怎么办，下一轮就都变（0，1）了，哪还有（1，1）🤓
[3.2.5页面分配策略](325页面分配策略/index.md)
  # 页面分配策略
    驻留集：系统给某进程分配的真实内存大小，被换出外存的部分不算
    - 驻留集太小会频繁缺页
    - 太大浪费空间
    驻留集分配策略：
    - 固定分配：分配固定大小，不再改变
    - 可变分配：运行期间可动态增减
  # 页面置换策略
    - 局部置换：缺页且内存不足时，只置换进程自己的块
    - 全局置换：缺页且内存不足时，在全局范围置换
    PS：
    1. 页面分配策略为固定分配时，无法使用全局置换
    1. 可变分配+全局置换并非最好，会导致其他进程缺页率增加，从而来回争抢，增加开销
  # 调入页面策略
    ### 预调页策略：
    根据局部性原理预测需要调入页面，在进程运行前提前调入
    ### 请求调入策略：
    运行时缺页再发出调入请求
  # 调入页面路径
    系统将磁盘分为对换区和文件区两部分
    对换区：连续存储（读写快）
    文件区：随机存储（读写慢）
    ### 对换区充足时
    - 所有的调入调出都在对换区进行
    ### 对换区不足时
    - 不需要修改的数据从文件区调入（不用写回）
    - 需要修改的数据从对换区调入

    ### UNIX方式
    - 某文件首次使用（对换区没有），直接从文件区调入
    - 调出时放到对换区，而不是文件区
  # 抖动（颠簸）现象
  刚调出的块立马又要调入就是抖动现象
  原因：分配给进程的物理块不够
  工作集：某段时间内进程访问了几个页面
  通过统计工作集来决定驻留集大小
[3.2.7内存映射文件](327内存映射文件/index.md)
  # 作用1：简化开发
  内存映射文件把文件内容直接映射到进程虚拟地址空间中，开发者不需要再显式调用 read()、write() 进行数据拷贝
  # 作用2：数据共享
  多个进程可以映射同一个文件实现文件共享
  传统做法：拷贝源文件到进程的内存中→修改→拷回去
  问题：a进程改了，b不能实时看到
  用进程映射文件就可以解决
  # PS
  使用内存映射文件后系统并不会立刻将对应文件拷到进程内存中，而是等运行到缺页时才会拷贝
  文件完全由操作系统负责，系统可以进一步优化io效率
