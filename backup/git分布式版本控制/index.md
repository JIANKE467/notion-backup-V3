  # 版本控制有两种方式
  ### 集中式版本控制
  如svn和cvs
  这两个已经过时，没必要学，没人用
  集中式版本控制只允许维护一个版本（必须连接远程仓库）
  ### 分布式版本控制
  如git 
  分布式版本控制允许每个人都能维护一个版本（不必须连接远程仓库）
  分布式版本控制允许两个人在没有中心服务器的情况下相互推送（一般不这么干）

  方法：
  在`/home/用户名`目录下创建一个`.bashrc`文件，并在该文件中输入
  ```shell
alias 命令别名='原命令'
#原命令可以带选项和参数
  ```
  然后打开git bash输入命令：`source ~/.bashrc`

[7. git常用命令（初始化/添加/历史/回退/忽略）](7-git常用命令初始化添加历史回退忽略/index.md)
  # 原理
  Git工作目录下对于文件的增删改会存在几个状态，这些状态会随着我们执行git命令而发生变化
  ![](assets/96e5a2dd-8276-83cf-b5bc-816ced0a3534.png)
  新创建的文件是未跟踪状态
  已有文件被修改是未暂存状态
  ### 用如下命令将修改/新增添加至暂存区
  ```shell
git add 文件名或通配符
#将文件添加入暂存区
  ```
  用通配符` . `表示所有文件/夹
  ### 用如下命令将暂存区文件提交至本地仓库
  ```shell
git commit [选项] 参数
#提交暂存区至仓库
  ```
  | 选项 | 含义 |
  | --- | --- |
  | -m（常用） | 添加提交说明 |
  | -a | 自动提交已跟踪文件（跳过 git add） |
  | --amend | 把本次提交合并到上一次提交（常用于修改提交信息或补交漏掉的文件） |
  | --no-verify | 跳过 pre-commit / commit-msg 等钩子校验（不建议常用） |
  **PS：**
  **Turtle git图形化界面将添加和提交一起执行了，实际上是两步，而不是直接提交**
  **PS：**
  **先添加后提交！**
  不添加-m，会自动弹出编辑器让你写备注
  ### 查看当前目录git控制状态（仓库中/未跟踪/未暂存/未提交）
  ```shell
git status
  ```
  ### 查看提交历史
  ```shell
git log [选项]
  ```
  | 选项 | 含义 |
  | --- | --- |
  | --all | 显示所有分支的提交历史 |
  | --oneline | 每条提交显示为一行（简洁显示） |
  | --graph | 用 ASCII 图形显示分支与合并历史 |
  | --decorate | 显示分支名、tag 等引用信息 |
  | -n 数字 | 只显示最近 n 条提交（例如 -n 5） |
  | --stat | 显示每次提交的文件变更统计 |
  | -p | 显示每次提交的具体 diff 补丁 |
  一般加入这些参数就直观了
  ![](assets/c735a2dd-8276-82ae-a6c5-817c09955051.png)
  （这里就可以使用Linux的指令别名，提前写好指令别名文件，降低调用指令所需的输入）
  ### 版本回退
  ```shell
git reset --hard 版本ID
  ```
  PS：
  版本ID可以用`git log`查看
  **复制版本ID不要ctrl+c（在Linux里，这是停止的意思）直接点击对应的版本ID就复制上了**
  **粘贴的时候也不要ctrl+v点一下鼠标滚轮就粘贴上了**
  同样的回退也可以撤销，同样的方法输入对应的版本ID即可（找不到ID可以执行`git reflog`）
  ### Git忽略
  只需要创建一个文件`.gitignore`，在里面写上相应的文件名或通配符，Git就会忽略
  注意`.gitignore`文件也需要提交才能生效y
[8. Git分支操作-常用指令](8-git分支操作-常用指令/index.md)
  一个仓库内允许有多个分支，这些分支可以让多个并行的版本共存，分支也可以合并，用来协作
  工作区只能挂载到一个分支上，看HEAD指向哪个分支
  # 查看分支
  ```shell
git branch
  ```
  # 创建本地分支
  **要先切换到对应的分支再创建，否则就创建到别的分支下了**
  ```shell
git branch 分支名
  ```
  # 切换分支（签出分支）
  ```shell
git checkout 分支名
  ```
  **创建并切换分支**
  ```shell
git checkout -b 分支名
  ```
  # 合并分支
  **要先切换到目标分支再合并，否则就合并到当前分支下了**
  ```shell
git merge 分支名
#先切换到要合并到的分支再执行
#分支名填要合并的分支名
  ```
  PS：一般都是其他分支合并到main/master分支
  所以一般都是先切到main/master分支，在执行get merge命令
  # 删除分支
  ```shell
git branch -d 分支名
  ```
  **强制删除**
  ```shell
git branch -D 分支名
  ```
  不能删除当前分支，要删除分支，得先切换到别的分支。
  **没有合并过的分支，直接删除会报错，git认为你误操作了，这个时候就要使用强制删除**
[9. 解决冲突（合并冲突）](9-解决冲突合并冲突/index.md)
  **当两个分支上同时修改了一个文件的同一行，这时就发生了冲突，需要手动解决冲突**
  **git逻辑：**
  **A. 当两个改动不在同一行，直接合并两种**
  **B. 当两个改动在同一行，将两种结果都写进去，人后期手动修改**
  步骤：
  1. 当发生冲突时，Git会自动把同一行的两种改动都写在文件里
  1. 这时打开冲突的文件
  1. 选择需要保留的内容，删除不需要的内容（也可以两个都删除，自己重新写一个）
  1. 添加到暂存区并重新提交
  1. 冲突解决
[10. 分支使用规范](10-分支使用规范/index.md)
  - master分支（生产）
  线上分支，主分支，中小规模项目作为线上运行的应用对应的分支

  - develop分支（开发）
  是从master创建的分支，一般作为主开发分支，开发完成再合并到master

  - feature分支（临时开发分支）
  名字不一定是feature，可以是功能或者其他的。要创建在develop分之下，合并到develop后可以删除。

  - hotfix/bug分支（bug修复分支）
  是从master分出来的分支。修复完成后合并回master，在合并给develop保持同步（因为规定master分支不合并到develop）

  - 有的还有test分支（测试）pre分支（预上线）….

  **注意⚠️：不要直接在develop分支上面开发，要先在develop分支上面创建一个新分支（featutre分支），在该分支上开发，开发完再合并会develop**
  **feature分支（临时开发分支）合并到develop分支以后可以删除**
  **develop分支合并到master分支后不要删除**
  **bug分支除了要合并到main分支以外还要合并给develop分支，否则main分支和develop分支数据不一致。**

[12.仓库托管](12仓库托管/index.md)
  # git远程仓库
  github（线上）
  码云（线上）
  gitlib（需要自己部署）
  # 步骤
  1. 先注册远程仓库
  1. 创建仓库
  1. 配置ssh秘钥（公钥放云，私钥放本地）
  - 设置→ssh秘钥→添加秘钥
  1. gitbath中验证是否配置成功
  ```shell
ssh -T git@平台网址
#平台网址指的是gitee.com或github.com,不是你的仓库地址
#执行这个命令要注意本地ssh私钥在本地默认路径上，否则会失败，详见ssh原理
#这是测试登录命令，能执行成功说明远程能用ssh登上
  ```
  1. gitbath中绑定仓库
  ```shell
git remote add 远程仓库名 仓库地址
#远程仓库名是给远程仓库起的别名，只对本机生效
#远程仓库名一般是“origin”
#一个本地仓库可以绑定多个远程仓库
#不绑定远程仓库就无法执行拉取/推送，因为git不知道本地仓库对应哪个远程仓库（即使能登陆上）
  ```
  推送/拉取/克隆
  PS：
  查看该私钥的远程仓库有哪些（远程仓库通过私钥来认人）
  ```shell
git remote
  ```
  # 配置ssh
  在shell中生成ssh秘钥对：
  ```shell
ssh-keygen -t rsa
  ```
  会提示设置文件路径（直接回车表示使用默认路径）
  会提示设置密码（直接回车表示不设置密码）
  ### 默认秘钥路径
  **公钥：**
  `~/.ssh/id_rsa.pub`
  直接cat命令查看
  ```shell
cat ~/.ssh/id_rsa.pub
  ```
  # ssh连接原理（ssh公钥已配置到服务器）
  使用ssh登录→
  客户端在本机默认位置寻找私钥→
  推导出公钥并发给服务器→
  服务器返回一个随机挑战→
  客户端用私钥签名并发给服务器→
  服务器用公钥验证→
  通过/不通过
[13. 推送/拉取/克隆](13-推送拉取克隆/index.md)
  # 推送
  ```shell
git push [-f] [--set-upstream][远程名称 [本地分支]：[远程分支]]
  ```
  PS：
  1. 本地/远程分支名一样,远端分支名可省略
  1. -f：强制推送（强制覆盖）
  1. `--set-upstream`：推送到远端的同时建立起和远端的分支关联关系
  1. 如果已经和远端建立分支关系，则可以省略：远端和本地分支名、远端名（直接git push就行）
  # 查看远程-本地分支对应
  ```shell
git branch -vv
  ```
  # 克隆
  ```shell
git clone 仓库路径 [本地目录]
  ```
  - 不填本地目录默认在当前路径
  # 抓取和拉取
  ### 抓取fetch
  ```shell
git fetch [远程分支] [本地分支]
  ```
  - 抓取命令只将远端更新下载到本地，不合并
  - 不指定远端和本地分支名，则抓取所有分支
  PS：
  **Q：抓取不涉及合并，那它怎么处理相同的部分？**
  **A：抓取会在本地创建一个“远端跟踪分支”，人手动合并本地分支和“远端跟踪分支”**
  ### 拉取pull（抓取+合并）
  ```shell
git pull [远程分支] [本地分支]
  ```
  - 拉取相当于抓取（fetch）+合并（merge）
  - 不指定远端和本地分支，拉取所有分支

[16.注意事项](16注意事项/index.md)
  ### 切换分之前先提交本地的修改
  为git并非一个分支一个文件夹，各分支的内容是混在一起的
  所以切换分支必须要覆写工作区，没有办法直接切换文件夹挂载（因为没有分文件夹）
  所以不提交直接切换工资，一定会导致修改丢失
