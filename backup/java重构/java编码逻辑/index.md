[方法/初始化顺序](方法初始化顺序/index.md)
  > **在Java中，逻辑希望被写进方法中，而不是直接写到类中（提升可维护性）**
  Java设计者希望你在类中初始化，在方法中写逻辑
  # 初始化顺序
  这里讲的初始化顺序是指程序运行时执行的先后顺序，不是内存装入顺序
  > **在Java中先进行类初始化，再进行对象初始化**
  ## 类初始化阶段
  - 静态变量（按代码顺序决定先后）
  - 静态代码块（按代码顺序决定先后）
  PS：静态代码块就是代码块前加`static`修饰符
  PS：静态方法不会自动执行，需要手动调用
  ## 对象初始化阶段
  Java的初始化是分层的（以下为执行顺序）
  1. 成员变量声明时初始化
  1. 初始化代码块
  1. 构造方法
  ```java
public class User {

    private String name = "张三";  // 成员变量初始化

    {
        System.out.println("初始化代码块执行");
    }

    public User() {
        System.out.println("构造方法执行");
    }
}
  ```
  PS：初始化代码块就是直接在类中编写逻辑，并用代码块包裹
[泛型](泛型/index.md)
  Java在泛型以前，各类是没有定义类型的
  也就是这样↓
  ```java
public class Test{
int a;
int b;
}
  ```
  但这带来一个问题：很多类型冲突只有运行时才能发现
  泛型推出以后，类型冲突可以在编译期被发现
  ## 泛型代表了什么
  方法的类型代表了返回值的类型
  而泛型的类型代表了该类允许传入的值（它是一个类型安全检查器）
  ## 类中要使用多种类型怎么办？
  泛型支持定义多种类型
  这就不得不提泛型的设计了，它没有设计成与方法传入参数一一对应的形式，而是由你定义一个或多个泛型变量及其对应的类型，在需要使用该类型的地方使用该泛型变量即可
  至于你说要一个参数支持多种类型，你总得先找到合适的数据类型来定义方法吧，只要找的到，泛型就定义的了
  ## 那为什么要在类签名上加泛型
  从功能上讲只要将泛型跟类型对应起来，再在相应位置使用泛型，就能达到目的了，为什么要在签名上加泛型？
  泛型必须在类签名上声明，否则编译器会认为泛型类是真实类（在类签名上声明是告诉编译器哪些是泛型类）
  这也回答了通配符只能在类调用的时候使用，在类定义时类签名中使用通配符是毫无意义的

  # 类加载时机
  Java的类是懒加载策略，只有被使用到才会被加载（有如下情况）
  - 使用子类时会先加载父类
  - 创建该类的对象
  - 访问该类的静态变量
  - 调用该类静态方法
  # 类加载顺序
  Java以整个.class文件（类文件）为单位进行加载，大致经历以下阶段
  ```java
加载（Loading）:载入类基本信息
   ↓
验证（Verification）
   ↓
准备（Preparation）:static变量分配空间，赋默认值
   ↓
解析（Resolution）
   ↓
初始化（Initialization）:执行static赋值和static代码块
   ↓
使用.     :创建对象...
   ↓
卸载（Unloading）
  ```

[链式调用应用场景](链式调用应用场景/index.md)
  Java的部分框架支持使用链式调用来操作
  链式调用的逻辑：方法接收一个对象的引用，在该引用上执行完自己方法的代码后将操作完的对象引用传出，这样就使得后一个方法可以直接跟在后面调用，这便是链式调用的核心原理
  因此链式调用不是什么新的底层特性
  # 支持的框架
  **Stream API（完全支持）：Java集合框架中的流式操作**
  Java多线程（部分支持）
  …….
  # 注意
  虽然都是流，JavaIO（即Java文件流）是完全不支持链式调用的
  Java多线程中的** ****`Thread`****、****`ExecutorService`****、****`Future`**** **不支持链式调用，**`CompletableFuture`**** **支持链式调用
