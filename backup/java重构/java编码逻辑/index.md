[方法/初始化顺序](方法初始化顺序/index.md)
  > **在Java中，逻辑希望被写进方法中，而不是直接写到类中（提升可维护性）**
  Java设计者希望你在类中初始化，在方法中写逻辑
  # 初始化顺序
  这里讲的初始化顺序是指程序运行时执行的先后顺序，不是内存装入顺序
  > **在Java中先进行类初始化，再进行对象初始化**
  ## 类初始化阶段
  - 静态变量（按代码顺序决定先后）
  - 静态代码块（按代码顺序决定先后）
  PS：静态代码块就是代码块前加`static`修饰符
  PS：静态方法不会自动执行，需要手动调用
  ## 对象初始化阶段
  Java的初始化是分层的（以下为执行顺序）
  1. 成员变量声明时初始化
  1. 初始化代码块
  1. 构造方法
  ```java
public class User {

    private String name = "张三";  // 成员变量初始化

    {
        System.out.println("初始化代码块执行");
    }

    public User() {
        System.out.println("构造方法执行");
    }
}
  ```
  PS：初始化代码块就是直接在类中编写逻辑，并用代码块包裹

  # 类加载时机
  Java的类是懒加载策略，只有被使用到才会被加载（有如下情况）
  - 使用子类时会先加载父类
  - 创建该类的对象
  - 访问该类的静态变量
  - 调用该类静态方法
  # 类加载顺序
  Java以整个.class文件（类文件）为单位进行加载，大致经历以下阶段
  ```java
加载（Loading）:载入类基本信息
   ↓
验证（Verification）
   ↓
准备（Preparation）:static变量分配空间，赋默认值
   ↓
解析（Resolution）
   ↓
初始化（Initialization）:执行static赋值和static代码块
   ↓
使用.     :创建对象...
   ↓
卸载（Unloading）
  ```

[JavaAPI](javaapi/index.md)
  进入泛型，匿名内部类后是不是感觉很乱，那是因为Java进入了新的阶段，也就是JavaAPI，这时不能在用原来的方式来分析代码
  那怎么办呢？

  学习方法：如学习一个类，只需要知道它实现了什么接口，功能是什么，有哪些方法，有什么注意事项？无需了解它是怎么实现的（顶多知道它是使用正常方法实现的接口还是匿名内部类实现的接口【知道对象引用给谁】），知道方法传入什么传出什么
  更深一点：知道类的继承关系
  所需技能：泛型，匿名内部类，Lambda表达式
  需要知道的点：Java一切皆对象（想用某个类？先创建对象）
